# OJ 在线判题系统 v2.0

## 版本概述

**版本号**: v2.0  
**发布日期**: 2026年5月  
**技术栈**: C++17 / ImGui / GLFW / OpenGL / MySQL / Docker Compose / Docker Sandbox / OpenSSL / Python3 / DeepSeek API  

v2.0 是项目从“终端交互式 OJ”升级到“桌面图形化 OJ”的重要版本。相比 v1.x，v2.0 引入了 Dear ImGui 图形界面、用户侧题目浏览与代码编辑窗口、管理员图形化添加题目、提交详情查看、Docker Compose 一键运行配置，以及更完整的本地开发与容器化部署文档。

本版本的目标不是把系统改造成 Web OJ，而是在保留 C++ 桌面程序形态的前提下，让用户可以通过图形窗口完成登录、选题、写代码、提交评测、查看提交记录和调用 AI 助手。

| 改进项 | v1.x | v2.0 |

## 与历史版本对比

### v0.x 到 v1.x：评测核心成型

v0.x 主要完成基础用户系统、题目系统、AI 接入设计和评测接口规划。v1.0 开始补齐 Docker 沙箱评测、容器池、逐测试点运行、提交入库、用户统计更新和 AI 错误上下文联动，项目从“功能设计”进入“可运行评测系统”阶段。

### v1.x 到 v2.0：使用体验升级

v2.0 的重点是把已经具备的评测能力包装成更可用的图形化程序：

- 用户不再依赖终端菜单，可以在窗口中完成主要操作。
- 题目列表、题目详情、代码编辑、评测结果和 AI 助手被统一放入 GUI 流程。
- 管理员可以通过表单添加题目，降低维护成本。
- 提交记录从“列表查看”升级为“列表 + 详情”。
- Docker 部署从散落的依赖说明收敛为 Compose 启动方式。

## 关键更新说明

### 1. 图形化页面状态机

v2.0 通过 `GUIState` 管理页面，例如：

- `MAIN_MENU`
- `USER_LOGIN`
- `PROBLEM_LIST`
- `PROBLEM_DETAIL`
- `SUBMIT_RESULT`
- `SUBMISSIONS_LIST`
- `SUBMISSION_DETAIL`
- `ADMIN_LOGIN`
- `ADMIN_MENU`
- `ADMIN_ADD_PROBLEM`

这种设计适合 ImGui 的即时模式渲染。每一帧根据当前状态调用对应页面绘制函数，页面切换只需要修改 `AppState::state`。

### 2. 用户提交详情

用户进入“查看我的提交”后，可以点击某条提交记录进入详情页。详情页展示：

- 提交 ID
- 题目编号和标题
- 提交时间
- 评测状态
- 状态原因说明
- 提交代码

当前版本的错误原因主要根据 `AC / WA / TLE / MLE / RE / CE / SE` 状态生成。逐测试点 diff、完整编译错误、运行 stderr 和资源使用明细仍属于后续增强方向。

### 3. 管理员添加题目

管理员登录后可以进入“添加题目”页面，通过表单录入：

- 标题
- 知识点
- 时间限制
- 内存限制
- 测试数据路径
- 题目描述

这比直接写 SQL 更适合普通管理员使用，也降低了误操作风险。

### 4. Docker Compose 启动

v2.0 推荐使用 Docker Compose：

```bash
docker compose up -d oj-db
docker compose run --rm oj-app
```

其中：

- `oj-db` 提供 MySQL 8.0 数据库。
- `oj-app` 编译并运行 C++ ImGui 主程序。
- `oj-app` 通过 Docker Socket 创建 `judge-sandbox:latest` 评测容器。
- `ai/.env` 保存用户本地 DeepSeek API Key，不进入版本库。

## 已知限制

| 限制项 | 说明 |
| ------ | ---- |
| 桌面 GUI | 当前不是 Web 服务，远程访问能力有限 |
| X11 依赖 | Docker 运行 GUI 需要宿主机支持图形转发 |
| 单语言 | 当前评测语言主要为 C++17 |
| 同步评测 | 提交后界面会等待评测完成 |
| 提交详情粒度 | 当前保存最终状态和代码，未保存完整逐点报告 |
| Docker Socket | `oj-app` 挂载宿主机 Docker Socket，适合本地实验环境 |
| 数据库安全 | 已使用转义降低风险，但还未全面使用 prepared statement |

---

## 总结

v2.0 的核心价值是把 v1.x 已经实现的 Docker 评测能力、数据库持久化和 AI 辅助能力整合进图形界面，让项目从“能运行的终端 OJ”升级为“可交互的桌面 OJ”。

后续版本应优先补强提交详情的数据完整性、评测异步化、管理员题目维护能力和数据库参数化访问。这些改进完成后，项目会更接近一个可长期维护的教学型 OJ 系统。
