# 安全边界分析

## 代码执行安全

用户代码运行在 Docker 沙箱中，不直接在宿主机执行。

主要隔离：

- `--network none`
- `--read-only`
- `--cap-drop=ALL`
- `--pids-limit=64`
- `--memory=256m`
- 非特权用户运行
- tmpfs 写目录

## Docker Socket 风险

`oj-app` 挂载宿主机 Docker Socket，用于创建评测沙箱。

这适合本地实验和课程项目，但不适合直接暴露给不可信用户。生产环境应拆分评测 worker，并限制 Docker 控制权限。

## 数据库安全

已实现：

- 密码哈希存储
- 输入转义
- 管理员和普通数据库账号区分

风险：

- 尚未全面使用 prepared statement
- 管理员操作缺少审计
- 数据库密码仍在配置中明文存在

## AI 密钥安全

`DEEPSEEK_API_KEY` 只应存在于本地 `ai/.env`，不应提交。

`.gitignore` 已忽略：

- `ai/.env`
- `.env`
- `.env.*`

同时保留：

- `ai/.env.example`
