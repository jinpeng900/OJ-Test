# 性能分析

## 当前性能瓶颈

| 点位 | 说明 |
| ---- | ---- |
| 同步评测 | GUI 会等待评测完成 |
| Docker 启动 | 新容器创建有冷启动成本 |
| AI 调用 | Python 子进程和外部 API 有明显延迟 |
| 数据库查询 | 目前缺少统一索引和分页策略 |
| 提交详情 | 未保存完整结构化评测报告，后续扩展会增加写入量 |

## 已有优化

- 容器池复用常驻容器。
- 常驻容器忙时按需创建临时容器。
- 使用 tmpfs 减少容器内磁盘写入。
- GUI 通过 `AppState` 缓存当前页面数据。

## 建议优化

### 异步评测

提交后立即返回 GUI，由后台线程执行评测，完成后刷新状态。

### 数据库索引

建议重点索引：

- `submissions(user_id, submit_time)`
- `submissions(problem_id)`
- `problems(category)`
- `users(account)`

### AI 复用

可将 Python AI 服务改为长驻进程，避免每次调用都创建 Python 解释器。

### 提交报告结构化

将逐测试点结果拆成 JSON 字段或独立表，避免详情页二次推断错误原因。
