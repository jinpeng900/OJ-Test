# 分层架构

## 总体结构

```text
main.cpp
  |
  v
ViewManager
  |----------------------|
  v                      v
AdminView              UserView
  |                      |
  v                      v
Admin                  User
  |                      |-------------|
  v                      v             v
DatabaseManager       JudgeCore      AIClient
                         |             |
                         v             v
                  ContainerPool    ai_service.py
                         |             |
                         v             v
                  SandboxContainer  DeepSeek API
```

## 分层职责

| 层级 | 模块 | 职责 |
| ---- | ---- | ---- |
| 入口层 | `main.cpp` | 初始化 GLFW、OpenGL、ImGui，进入主循环 |
| GUI 控制层 | `ViewManager` | 保存 `AppState`，按 `GUIState` 分发页面 |
| 视图层 | `UserView` / `AdminView` | 绘制页面，处理按钮和表单 |
| 业务层 | `User` / `Admin` | 登录、提交、题目管理、统计更新 |
| 数据层 | `DatabaseManager` | MySQL 连接、查询、转义 |
| 评测层 | `JudgeCore` | 编译、运行、比对、生成报告 |
| 沙箱层 | `ContainerPool` / `SandboxContainer` | Docker 容器复用、隔离执行 |
| AI 层 | `AIClient` / `ai_service.py` | 传递上下文并调用 DeepSeek |

## 关键架构选择

- GUI 使用即时模式 ImGui，因此页面不能阻塞等待用户输入，只能每帧根据状态渲染。
- 业务逻辑尽量放在 `User` 和 `Admin`，避免视图层直接操作数据库。
- 评测逻辑通过 `JudgeCore` 封装，GUI 只关心 `JudgeReport`。
- Docker 调用通过 CLI 实现，不引入 Docker SDK。
- AI 通过 Python 子进程实现，避免在 C++ 里直接维护大模型 SDK。
